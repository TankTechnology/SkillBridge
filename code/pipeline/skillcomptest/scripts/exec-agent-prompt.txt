evidence. Read the detailed workflow at $REPO_ROOT/Agents/ExecAgent/platform/workflow.md
for the required output format (platform_summary.json, platform_report.md, etc.).

Platform: $PLATFORM (this is the OS you are running on RIGHT NOW)

## PORTABILITY-FIRST EXECUTION

Read $SAMPLE_OUT/benchmark_manifest.json, then read each task's
task_description.md. For every task:

### 1. Pre-flight environment check
Before executing, record the actual platform environment:
- OS and version
- Available runtimes (python, node, etc.) and their versions
- Available package managers
- Filesystem type and encoding
- Shell type
- Browser/GUI availability
- Network access

### 2. Execute with platform awareness
Execute the task on $PLATFORM. Pay attention to:
- Does the task fail because of a platform-specific assumption in the SKILL?
- Does the task work correctly on $PLATFORM?
- Does the task produce meaningful blocked/unsupported when appropriate?

### 3. Classify using canonical taxonomy
For each task, assign ONE of: pass | fail | blocked | unsupported
Read $REPO_ROOT/Agents/PORTABILITY_BENCHMARK.md for detailed guidance on
each classification.

If the status is NOT pass, also assign a failure_category from:
missing_dependency | missing_capability | os_api_incompatible |
path_shell_assumption | permission_model | gui_or_browser_unavailable |
network_or_service | encoding_locale | packaging_or_install |
runtime_crash | logic_error | unknown

And a portability_blocker_type:
skill_issue | environment_issue | platform_issue | mixed

### 4. Write per-task evidence
For EACH task, write to $EXEC_OUT/tasks/{task_id}/:
- results/task_output.json (the parseable output contract)
- results/task_metrics.json (execution metadata)

### 5. Write aggregate outputs

Write to $EXEC_OUT/:

**platform_summary.json** — MUST match this EXACT schema:
```json
{
  "skill": "source/skill-name",
  "platform": "$PLATFORM",
  "pass_count": 0,
  "fail_count": 0,
  "blocked_count": 0,
  "unsupported_count": 0,
  "platform_success_rate": 0.0,
  "portability_verdict": "full_support|partial_support|blocked|unsupported",
  "failure_categories_observed": [],
  "portability_blocker_types": [],
  "environment_summary": {
    "os": "",
    "shell": "",
    "available_runtimes": [],
    "available_browsers": [],
    "network": true|false,
    "disk_writable": true|false,
    "critical_blockers": []
  }
}
```

CRITICAL RULES:
- `pass_count` + `fail_count` + `blocked_count` + `unsupported_count` MUST equal 10
- `platform_success_rate` = pass_count / 10
- `failure_categories_observed` uses the canonical taxonomy from PORTABILITY_BENCHMARK.md
- `portability_verdict`: "full_support" if >=8 pass, "partial_support" if 5-7 pass, "blocked" if mostly blocked, "unsupported" if mostly unsupported
- DO NOT nest counts under a "summary" key — they must be at top level
- DO NOT use string percentages like "10%" — use floats like 0.1

**platform_report.md** — detailed per-task analysis with platform evidence
**run_manifest.json** — execution manifest
**metrics.json** — timing and resource metrics

CRITICAL: Record explicit environment evidence for every task. A task judged
'blocked' without evidence of WHICH dependency is missing is incomplete.
A task judged 'unsupported' must explain WHY the platform fundamentally
cannot support it.
