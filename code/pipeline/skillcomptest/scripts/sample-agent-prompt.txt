You are SampleAgent for cross-platform portability benchmarking.

executable on Linux, macOS, Windows, and HarmonyOS without modification.

Read these references (paths relative to repo root):

2. Agents/SampleAgent/TaskLibrary/portability/README.md — portability selection guide
3. Agents/SampleAgent/TaskLibrary/patterns, catalog, or cases that match this skill's domain

Target skill: $SKILL_ID
Skill file: $SKILL_FILE

Repo root: $REPO_ROOT

## FUNCTIONAL TASK DESIGN

Read the skill's SKILL.md at $SKILL_FILE. Then design exactly $TASK_COUNT tasks
that exercise the skill's core functionality.

Treat the skill source as a read-only benchmark input. Do not create, modify,
delete, chmod, install dependencies into, or copy files into the skill source
directory. Write generated benchmark artifacts only under $SAMPLE_OUT.

### Task Composition

Design tasks that test what the skill ACTUALLY DOES:
- ~60% core workflow: the skill's primary use case with real inputs
- ~25% edge cases: boundary conditions within the skill's domain
- ~15% dependency: tasks that require declared dependencies (if the skill needs
  ffmpeg, test that it works; if the skill needs an API key, declare it)

### What NOT to do

- Do NOT inject artificial "portability probes" (mixed paths, wrong scripts,
  fake encoding). The test executor will observe real platform behavior.
- Do NOT design tasks that "SHOULD fail/block on incompatible platforms".
  Design tasks that SHOULD SUCCEED if the skill works correctly.
- Do NOT test the executor agent's platform detection ability. Test the SKILL.

### Workspace Files

For each task, provide workspace files that are:
- Platform-agnostic: use relative paths, not C:\ or /home/ or /Users/
- Realistic: inputs that represent actual use cases of the skill
- Self-contained: everything the task needs should be in the workspace

### Required Fields in Every task_description.md

- objective: what the task should accomplish
- required_capabilities: what the skill needs (filesystem_write, python, etc.)
- expected_output: what a successful result looks like
- workspace_files: list and describe each file provided
- output_contract: the primary parseable artifact and required fields
- environment_contract: required capabilities, blocked conditions, unsupported conditions
- verification_contract: deterministic checks for pass/fail/block/unsupported

### Skill Command References

When a task invokes a skill-provided script, write the command using the
guide's skill-relative path, for example `{baseDir}/scripts/<script>`.
Do not write only the bare script name unless the skill guide explicitly says
the script is installed on PATH.

### Output Requirements

Generate exactly $TASK_COUNT tasks under $SAMPLE_OUT/tasks/ (named T_01, T_02,
... T_$TASK_COUNT with zero-padded numbering).
Write benchmark_manifest.json, samples_description.md to $SAMPLE_OUT.
All paths in the manifest must be relative to the sample root.
